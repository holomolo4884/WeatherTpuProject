# Курсовой проект по теме POCO - создать HTTP-клиент для выполнения GET-запросов к удалённому серверу и вывода полученных данных

![CI](https://github.com/holomolo4884/WeatherTpuProject/actions/workflows/ci.yml/badge.svg)

Учебный проект на C++ с использованием библиотеки [POCO C++ Libraries](https://pocoproject.org).

Клиент отправляет серверу название города. Сервер находит город и запрашивает прогноз на 5 дней
у сервиса [Open-Meteo](https://open-meteo.com) (бесплатный, ключ API не нужен), формирует компактный
JSON и возвращает его клиенту. Клиент разбирает ответ и выводит прогноз в консоль в виде таблицы.

## Архитектура

```
┌────────┐  GET /weather?city=Moscow   ┌────────────┐  HTTPS  ┌──────────────────────┐
│ Клиент │ ──────────────────────────> │   Сервер   │ ──────> │ Open-Meteo Geocoding │  город -> координаты
│        │                             │ 127.0.0.1  │ ──────> │ Open-Meteo Forecast  │  координаты -> прогноз
│        │ <────────────────────────── │   :8080    │ <────── │                      │
└────────┘        JSON (5 дней)        └────────────┘         └──────────────────────┘
    │
    └─> таблица в консоли
```

- **Клиент** (`client/main.cpp`): принимает название города (аргумент командной строки или ввод с клавиатуры),
  собирает запрос через `Poco::URI` (кириллица и пробелы кодируются автоматически), отправляет его
  через `HTTPClientSession`, разбирает JSON-ответ (`Poco::JSON`) и печатает таблицу.
- **Сервер** (`server/main.cpp`): `Poco::Net::HTTPServer` на порту 8080. Запросы обрабатываются в пуле
  потоков POCO. На один запрос клиента сервер делает два HTTPS-запроса к Open-Meteo:
  геокодинг (город -> широта и долгота) и прогноз (координаты -> 5 дней).

## Требования

- macOS или Linux, компилятор с поддержкой C++17 (clang или gcc)
- CMake 3.16 или новее
- POCO C++ Libraries (модули Foundation, Net, NetSSL, JSON, Util)
- OpenSSL 3
- Доступ в интернет (для запросов сервера к Open-Meteo)

## Установка и сборка

**macOS (Homebrew):**

```bash
brew install cmake poco openssl@3
cmake -B build -DCMAKE_PREFIX_PATH="$(brew --prefix)" -DOPENSSL_ROOT_DIR="$(brew --prefix openssl@3)"
cmake --build build
```

**Ubuntu/Debian:**

```bash
sudo apt-get install cmake g++ libpoco-dev libssl-dev
cmake -B build
cmake --build build
```

После сборки в папке `build/` появятся два исполняемых файла: `weather_server` и `weather_client`.

## Запуск

Нужны два терминала.

**Терминал 1: сервер** (работает, пока вы не нажмёте Ctrl+C):

```bash
./build/weather_server
```

**Терминал 2: клиент:**

```bash
./build/weather_client Moscow
./build/weather_client "Санкт-Петербург"
./build/weather_client New York
./build/weather_client            # без аргумента программа спросит город
```

Код возврата клиента: `0` при успехе, `1` при любой ошибке.

## Протокол обмена между клиентом и сервером

Запрос:

```
GET /weather?city=<название города>
```

Успешный ответ (`200 OK`, `application/json`):

```json
{
  "city": "Москва",
  "country": "Россия",
  "latitude": 55.75204,
  "longitude": 37.61781,
  "days": [
    {"date": "2026-11-18", "tmin": -0.5, "tmax": 0.5, "precip": 9.2, "wind": 12.7}
  ]
}
```

| Поле | Значение |
|---|---|
| `date` | дата по местному времени города |
| `tmin`, `tmax` | минимальная и максимальная температура, °C |
| `precip` | сумма осадков за день, мм |
| `wind` | максимальная скорость ветра, км/ч |

Ответ с ошибкой содержит тело `{"error": "<описание>"}`.

## Обработка ошибок

| Ситуация | HTTP-код сервера | Сообщение клиента |
|---|---|---|
| Параметр `city` не указан или пустой | 400 | `Сервер вернул ошибку (400): city is required` |
| Город не найден | 404 | `Сервер вернул ошибку (404): city not found` |
| Неверный путь | 404 | `Сервер вернул ошибку (404): not found` |
| Метод, отличный от GET | 405 | `Сервер вернул ошибку (405): only GET is allowed` |
| Open-Meteo недоступен или отвечает слишком долго | 502 | `Сервер вернул ошибку (502): weather service unavailable` |
| Сервер не запущен | - | `Ошибка соединения с сервером: Connection refused` |
| Сервер вернул некорректный JSON | - | `Некорректный ответ сервера: ...` |
| Пустой ввод города | - | `Ошибка: название города не указано` |

Таймауты: сервер ждёт каждый ответ Open-Meteo не дольше 5 секунд, клиент ждёт сервер не дольше 30 секунд.

## Тестирование

Тесты запускаются через CTest. Он сам поднимает сервер перед тестами и останавливает после
(перед запуском остановите вручную запущенный сервер: тесты используют порт 8080).

```bash
ctest --test-dir build --output-on-failure              # все тесты
ctest --test-dir build -LE network --output-on-failure  # только тесты без внешнего интернета
ctest --test-dir build -L network --output-on-failure   # только тесты, которым нужен Open-Meteo
```

Что проверяется:

| Тест | Ожидание |
|---|---|
| `http_moscow`, `http_cyrillic`, `http_space_in_name` | 200 для обычного города, кириллицы и названия с пробелом |
| `http_unknown_city` | 404 для несуществующего города |
| `http_empty_city`, `http_no_city` | 400 при пустом или отсутствующем `city` |
| `http_bad_path` | 404 для неизвестного пути |
| `http_post_method` | 405 для метода POST |
| `client_moscow` | клиент печатает «Прогноз погоды: Москва» |
| `client_unknown_city` | клиент печатает «city not found» |

Тесты, которым нужен внешний интернет, помечены меткой `network`: Open-Meteo иногда отвечает
медленно, и такой сбой не связан с кодом проекта.

Два сценария проверяются вручную:

| Сценарий | Как проверить | Ожидание |
|---|---|---|
| Сервер выключен | остановить сервер, запустить клиент, выполнить `echo $?` | `Connection refused`, код возврата 1 |
| Нет интернета на сервере | отключить Wi-Fi при работающем сервере, запустить клиент | через несколько секунд ответ 502; после включения Wi-Fi запрос снова проходит без перезапуска сервера |

## Непрерывная интеграция

Workflow GitHub Actions (`.github/workflows/ci.yml`) при каждом push и pull request собирает проект
на Ubuntu и macOS и запускает тесты. Результат тестов без сети определяет статус сборки; тесты
с внешним API запускаются отдельным шагом с повторными попытками и не роняют сборку при временной
недоступности Open-Meteo.

## Ограничения

- Проверка SSL-сертификатов при запросах к Open-Meteo отключена (`VERIFY_NONE`). Для промышленного
  использования её нужно включить.
- Нет кэширования: каждый запрос клиента приводит к двум запросам к Open-Meteo, поэтому первый запрос
  для города может быть медленным.
- Адрес и порт сервера (`127.0.0.1:8080`) заданы в коде, а не через аргументы командной строки.
- Сервер слушает только IPv4. Поэтому клиент обращается к `127.0.0.1`, а не к `localhost`: на macOS
  `localhost` может превратиться в IPv6-адрес `::1`, и соединение будет отклонено.
- Название города берётся первым результатом геокодинга: для неоднозначных названий (например, одинаковых
  в разных странах) выбранный город может отличаться от ожидаемого.
